## Product interfaces and behavior

Implement the accepted G07 fixture exactly, with the contract's named private
helpers and constants. One `127.0.0.1` bind, actual local_addr port, one handler,
one request/connection, no business clock or dynamic backend. HTTP parser is
httparse =1.10.1/defaults false; framing policy and bounded IO are transport
helpers, not a replacement HTTP or JSON parser. Header/body reads <=8192/257,
<=32 headers, total read/write budgets 5s/5s. Close without draining/retrying.

Preserve exact JSON application headers; add only length/close framing. No
fake asset 200 or error-to-success conversion. Contract owns HEAD/transport
errors/disconnect semantics and startup URL output.

Named socket tests (every one must execute, not skip):

- `server_serves_exact_assets_and_typed_json`: eight approved routes, full
  initial state/catalog/teaching, all six nonempty assets and MIME, exact
  application/framing headers, declared lengths and no Date/Server/CORS/cookie.
- `server_preserves_raw_target_method_and_duplicate_headers`: wrong Host/
  actual-port mismatch, duplicate Host/Origin/Content-Type, off-origin, percent/
  query/dot/absolute/backslash targets, unknown targets, lowercase methods,
  HEAD/OPTIONS; exact handler status/code/Allow and unchanged state. HEAD has
  zero wire body but correct corresponding encoded length and rejection status.
- `server_rejects_framing_without_mutation`: TE including chunked, TE+CL,
  duplicate equal/different CL, malformed/overflow/leading-zero CL, Expect,
  Upgrade, folding, header-name whitespace, NUL/bare LF/non-ASCII/leading blank
  line/extra request-line token, >32 headers and >8192 head; empty transport
  400/431 with exact headers; incomplete EOF never succeeds.
- `server_bounds_body_and_closes_without_draining`: valid padded JSON of
  exactly 256 bytes succeeds; 257 yields typed 413; a huge declared CL with
  exactly 257 sent promptly yields 413 and closes while sender remains open.
  Fixed arrays/call bounds require direct code review as well; wire status
  alone cannot prove total allocation bounds.
- `server_slow_partial_clients_expire_and_next_request_works`: incomplete head
  and body hit total read deadline; a trickle of bytes does not reset it;
  next connection succeeds with state unchanged. Use real five-second budgets
  and bounded watchdog with scheduling tolerance, not a production test knob.
- `server_actions_are_single_request_and_disconnect_does_not_reset`: exercise
  all four actions/Reset and subsequent GET; pipeline a second mutating request
  and prove it never applies. After valid POST then disconnect, permit state
  before/after application according to arrival timing, never another state;
  a separate unit test supplies a connected server stream whose write half was
  shut down, sends a complete valid action, and verifies the shared handler
  applied it despite write failure, without rollback/second apply. Server
  remains usable and does not automatically retry.
- `server_public_run_process_stop_and_restart_restore_fixture`: child fixture
  calls public run(0), discovers actual port from the exact stdout line, checks
  bind/GET/actions, terminates with an incomplete body outstanding, reaps it,
  restarts and compares the full initial state. Bind-conflict returns Err.
