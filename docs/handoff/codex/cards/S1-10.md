## Actual process and byte comparison

Use `env!("CARGO_BIN_EXE_sovereign")`, which Cargo supplies to the integration
test for the actual CLI binary. Run the acceptance target with `--release` so
the compared processes execute the shipped release command; no alternate
binary-selector environment variable or production option is introduced.

Run two distinct processes sequentially. A starts with `playground --port 0`;
read and validate the server's exact startup line and trusted actual port.
After its complete transcript, stop/reap A. B starts with
`playground --port <same_actual_port>` and a different fake platform root.
Run the identical request bytes in the identical order. Same-port sequential
execution is intentional: stdout and all wire responses can then be compared
byte-for-byte, including startup URL, headers, lengths and bodies. There is
no port substitution, JSON reserialization, header sorting, timestamp removal,
or selective transcript comparison. A reused-port bind collision fails with a
named environmental diagnostic; never silently choose another port or weaken
comparison. Two distinct child PIDs and completed cleanup must be recorded.

Each run's ordered transcript includes:

1. All six GET assets and initial GET `/api/playground/consultant`.
2. `ShowReportingSearch`, GET; `CorrectOfferPrice`, GET; repeat correction,
   GET; `PromoteAcmeToCustomer`, GET; repeat promotion, GET; search, GET.
3. `Reset`, GET; promote before correction, GET; correct, GET; Reset, GET.
4. Invalid action, extra field, malformed JSON, unknown route, wrong method,
   wrong Host and wrong Origin; GET after each proves full state unchanged.
5. Correct price and promote again, then GET; stop with this changed state
   still in memory, so B's initial fixture also proves restart reconstruction.

Construct only the frozen raw requests/JSON action bodies, with fixed
Content-Length. Success and error statuses must match accepted HTTP behavior;
compare full parsed GET values for expected fixture/action semantics in
addition to full raw equality. Use the real response catalog, not another
copied bilingual fixture. The first GET in B equals A's initial GET, proving
fresh process state; Reset and search are also verified from the complete
responses. Existing S1-07 tests own exhaustive transport attacks/deadlines;
do not duplicate that suite here.

Collect every stdout/stderr byte through child termination, not just the first
line. Expected stdout is exactly the fixed startup URL line, stderr empty.
Assert neither root's distinct canary byte sequence appears in any HTTP,
stdout or stderr byte, and that at least one successful response was collected
for each expected transcript step. Both independent roots must remain
recursively identical to their respective before snapshots after both runs.
Root A and root B are deliberately unequal to one another.

## Fixed fake-root fixture and support reuse

Use existing CLI dev dependency `tempfile`. The sole added dev dependency is
`httparse = { version = "=1.10.1", default-features = false }`, matching the
already locked S1-07 parser; there is no new registry package/version or root
manifest edge. This declaration is necessary because Rust integration tests
cannot use a transitive dependency through the Playground crate. Each independent
TempDir contains a child home, an XDG data root and a working directory. Seed
the potential platform data locations with different obvious synthetic canary
bytes in `sovereign-founder-os/device.json`, `ledger.json`, a file under
`vault/`, and a nested unrelated sentinel. These need not be valid product
state: Playground must not inspect them. Snapshot the entire TempDir, including
empty directories and the work directory, before launch.

Set HOME and XDG_DATA_HOME only on each test-owned child Command and set its
current_dir to that fixture's work directory; never mutate parent environment
or shell HOME. On Linux cover the explicit XDG root and home `.local/share`
fallback; on macOS cover home `Library/Application Support`. Installed dirs
5.0.1/dirs-sys 0.4.1 use these locations; keep their source observation in the
report. This is scoped to actual Linux/macOS execution; unsupported hosts
must return an explicit failure, not a skipped passing test or a Windows
isolation claim. No original user data path is read or inventoried.

New declared test-only fixture interfaces in support/isolation.rs:

```rust
pub(crate) struct FakeRoot {
    root: tempfile::TempDir,
    home: std::path::PathBuf,
    xdg: std::path::PathBuf,
    work: std::path::PathBuf,
}
impl FakeRoot {
    pub(crate) fn new(canary: &'static [u8]) -> std::io::Result<Self>;
    pub(crate) fn configure(&self, command: &mut std::process::Command);
    pub(crate) fn snapshot(&self) -> std::io::Result<TreeSnapshot>;
}
pub(crate) type TreeSnapshot = std::collections::BTreeMap<std::path::PathBuf, TreeEntry>;
#[derive(Debug, Eq, PartialEq)]
pub(crate) struct TreeEntry {
    mode: u32,
    modified: std::time::SystemTime,
    contents: Option<Vec<u8>>, // None = directory; Some = regular file.
}
```

The fixture enumerator errors on symlinks/unexpected types/read failures,
preserves empty directories, and does not ignore unknown files. Access time
is excluded because snapshot reads themselves may update it; report this
limit. This bounded test-tree inventory is not a production serializer,
security scanner or general filesystem framework. Ordinary std IO/BTreeMap
and byte comparison suffice; no duplicate hashing/canonical JSON tool.
