# S0-01 — 项目模型配置与真实分派

**Revision 2 · Spec Frozen · 执行角色：worker。**运行状态唯一见 [backlog](../../../backlog.md)。分派前必须由 controller 填入当前 base_commit、卡 blob 与唯一报告路径；未填不得施工。

## 目标与前置

在项目内配置 Luna medium worker 和强模型 reviewer/fallback/architect，取得真实工具分派回报。保持全局配置和现有定时任务不变。

S0-00 文档契约已验收；无其他实现依赖。若用户已切换 Luna，先按 [自举流程](../models-and-goals.md#bootstrap-controller) 调用强模型 bootstrap controller，再由它认领本卡。此卡不会让 Luna 在 S0 验收前自行担任 controller。

## 精确写入集合

- .codex/config.toml
- .codex/agents/founder-worker.toml
- .codex/agents/founder-reviewer.toml
- .codex/agents/founder-fallback.toml
- .codex/agents/founder-architect.toml

另允许 controller 指定的本卡单一 worker report 文件。队列、卡、protocol/contracts、角色规范、全局 gate 与其他卡文件禁止 worker 改动。实现校验工具的卡只获准修改上列对应工具与测试，不因此取得改变自己验收标准的权限。

## 接口与做法

只使用 [models-and-goals.md](../models-and-goals.md) 已核实的配置字段。角色模型从该文件读取，不在本卡复制。角色职责引用 protocol；worker 接收独立冻结简报，reviewer 独立读取 candidate。

1. 先检查是否已有项目配置；存在则保留无关键，不整体覆盖。
2. 配置 worker/reviewer/fallback/architect；主线程默认 Luna medium。不要假设自定义 Agent 的 sandbox 覆盖了父任务运行时权限。
3. 对 worker 与 reviewer 各派一个只读、无真实业务数据的小任务；保留调用时明确指定的模型/推理参数、工具返回 ID 和实际可观察信息。使用允许显式模型覆盖的独立上下文，不把完整历史继承的默认模型当成强模型。禁止把模型在文本中的自报型号当唯一证明。
4. 若当前工具不接收角色名，用明确 model/effort 及同一角色简报做 smoke；报告分别记录‘配置文件存在’和‘实际分派路径’，不得谎称验证了未调用的配置加载。
5. 记录强模型 controller 能否直接嵌套分派，以及任务结束后的槽位行为。不支持时采用自举流程中已规定的主线程转发，明确谁决策、谁调用；不得临时设计另一套调度器。

## 验收

以下新增测试/检查为 **planned**，不得在报告里预填通过。先确认测试已存在且实际执行，零测试/跳过不通过。

- 检查 TOML 被实际客户端接受或明确记录加载未验证；必须存在一条可用的显式分派路径。
- worker 与 reviewer 均返回；模型不可用或被拒绝时报告 blocked，不回落到默认模型。
- reviewer 的只读要求、继承权限的实际边界写进报告。
- 从用户的 Luna 主线程到强模型 controller，再到 worker/reviewer 的可用调用路径有实际证据；后续 S0 可按它逐卡执行。

~~~bash
git diff --check
./scripts/test_changed.sh
~~~

不安装插件、不改用户 ~/.codex 配置、不创建 Goal/automation、不修改源码或假定账号额度无限。

## 交接

按 [protocol](../protocol.md) 报告 candidate、diff --stat、新文件、真实检查、复用/新增工具和剩余问题；worker 交付即停，controller 分派独立 reviewer。两次失败与环境阻塞按该协议处理，不能在本卡另定一套。

工具清单唯一维护于 [protocol §10.2](../protocol.md)，controller 分派简报时展开实际相关条目并补充已落地 S0 接口。新开发工具的必要性已在 [contracts §1](../contracts.md) 申报；除此以外的新工具必须先申报。

> 复用以上，禁止重新实现同类工具；需要新工具先在简报回复中申报。
