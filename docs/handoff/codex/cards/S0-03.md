# S0-03 — Git candidate 与真实检查证据

**Revision 1 · Spec Frozen · 执行角色：worker。**运行状态唯一见 [backlog](../../../backlog.md)。分派前必须由 controller 填入当前 base_commit、卡 blob 与唯一报告路径；未填不得施工。

## 目标与前置

检查实际 Git 改动与冻结卡一致，执行获准检查并记录真实结果，拒绝旧 head、漏文件和虚假绿色。

S0-02 已验收。

## 精确写入集合

- scripts/codex-control/git.mjs
- scripts/codex-control/git.test.mjs
- scripts/codex-control/checks.mjs
- scripts/codex-control/checks.test.mjs
- scripts/codex-control/test-support.mjs

另允许 controller 指定的本卡单一 worker report 文件。队列、卡、protocol/contracts、角色规范、全局 gate 与其他卡文件禁止 worker 改动。实现校验工具的卡只获准修改上列对应工具与测试，不因此取得改变自己验收标准的权限。

## 接口与做法

实现 [contracts §4](../contracts.md) 的 inspectCandidate / runChecks / verifyEvidence。唯一 Git subprocess 包装放 git.mjs。测试共享临时仓库 fixture 放 test-support.mjs；同用途 helper 禁止复制到每个测试文件。

1. 用临时 Git 仓库写测试，不改当前真实工作树状态。
2. 采用 argv 调用 Git/测试；核对实际对象、祖先、卡 blob、rename/delete、新增及未跟踪文件。
3. runChecks 只执行冻结 CheckSpec，捕获退出、timeout、完成与测试数，写入批准的临时日志目录。
4. verifyEvidence 拒绝错 task/revision/candidate、缺检查、重复结果、不同 argv、skipped 与无法证明执行。

- untracked_outside_scope_is_rejected

- nonzero_timeout_and_spawn_error_fail_closed
