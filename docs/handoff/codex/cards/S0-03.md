# S0-03 — Git candidate 与真实检查证据

**Revision 2 · Spec Frozen · 执行角色：worker。**运行状态唯一见 [backlog](../../../backlog.md)。分派前必须由 controller 填入当前 base_commit、卡 blob 与唯一报告路径；未填不得施工。

## 目标与前置

检查实际 Git 改动与冻结卡一致，执行获准检查并记录真实结果，拒绝旧 head、漏文件和虚假绿色。

S0-02 已验收。

- scripts/codex-control/git.test.mjs

另允许 controller 指定的本卡单一 worker report 文件。队列、卡、protocol/contracts、角色规范、全局 gate 与其他卡文件禁止 worker 改动。实现校验工具的卡只获准修改上列对应工具与测试，不因此取得改变自己验收标准的权限。

## 接口与做法

实现 [contracts v2 §4](../contracts.md) 的 inspectCandidate / runChecks / verifyEvidence / getCommonDir；字段检查直接复用 state.mjs 已导出的三个共享接口。唯一 Git subprocess 包装放 git.mjs。测试共享临时仓库 fixture 放 test-support.mjs，导出 withTempRepo；同用途 helper 禁止复制到每个测试文件。

1. 用临时 Git 仓库写测试，不改当前真实工作树状态。
2. 采用 argv 调用 Git/测试；核对完整契约历史、实际对象、祖先、基线上的卡/输入 blob、rename/delete、新增及未跟踪文件。按 [protocol §9.6.1](../protocol.md) 测试 B/C/W/R 提交关系；检查器只检查 HEAD=W 的候选 worktree，报告及 controller 记录由上层独立核对。
3. runChecks 只执行冻结 CheckSpec，按四种 completion 判据捕获退出、timeout、完成与测试数，写入批准的临时日志目录。正常无输出命令可成功；scoped gate 必须固定契约基线和自检/日志环境变量，同时核对 stdout 与详细日志，不能漏掉继承环境导致的缩小检查范围或缺 npx 的 SKIPPED。
4. verifyEvidence 拒绝错 task/revision/candidate、缺检查、重复结果、不同 argv、skipped 与无法证明执行。
