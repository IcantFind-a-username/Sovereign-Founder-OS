## Sole shared helper contract

Keep `Response { status, headers, body, raw }`, connect, raw_request, request
and read_response signatures and behavior unchanged. Reuse request's complete
raw bytes and its httparse-owned response parser; do not add a second parser
or response serializer. Extend the existing ChildServer only:

```rust
impl ChildServer {
    pub fn start() -> std::io::Result<Self>; // unchanged S1-07 convenience
    pub fn start_mode(mode: &str) -> std::io::Result<Self>; // unchanged fixture selector
    pub fn start_command(command: std::process::Command) -> std::io::Result<Self>;
    pub fn id(&self) -> u32;
    pub fn stop(&mut self) -> std::io::Result<std::process::ExitStatus>; // preserved
    pub fn captured_output(&self) -> std::io::Result<(&[u8], &[u8])>;
}
```

The caller supplies its already configured Command. No binary-selector env
variable, command shell or production entry is introduced. start_mode builds
its existing fixture Command and delegates to start_command; there is exactly
one spawning, startup-detection, capture and cleanup implementation.

start_command overrides stdout/stderr to piped, installs the child cleanup
guard immediately after spawn, and starts one continuously draining reader per
pipe. Capture **every byte**, including fixture harness preamble and bytes
following startup. Preserve existing canonical nonzero-port startup parsing:
one exact `Playground: http://127.0.0.1:<port>\n` line found within the first
4096 stdout bytes, within three seconds. S1-07 fixture preamble is retained,
not removed; the real CLI's complete-output assertion separately requires its
stdout to equal that single line. id returns the real OS child PID.

Each pipe has a 65536-byte total capture bound, implemented with a fixed-size
read buffer and checked remaining capacity. Overflow, read error, missing or
malformed startup, reader panic or incomplete capture fails the test; never
silently truncate or return a partial successful output. Both readers run
concurrently so one full pipe cannot block draining the other. Interrupted
reads retry; other errors remain errors. A post-start capture failure must
surface from stop/captured_output, not disappear after the startup channel
has succeeded. Factoring one private bounded capture loop for both pipes is
authorized; no general process/IO framework is added.

stop kills the direct child if still running, waits/reaps it, and joins both
readers before marking complete output available. Preserve its ExitStatus
return type and repeat-call cleanup safety. On any failure still attempt all
cleanup steps; an early error must not strand the other reader or the child.
Drop uses that same cleanup implementation and cannot report success. Startup
timeouts also kill/wait/join. Accepted run creates no descendants, and the
test fixtures must not create any pipe-inheriting descendants; do not add
process-tree management or detach reader threads to evade cleanup. Preserve
S1-07's existing startup/panic-cleanup watchdog checks. captured_output returns
borrowed complete stdout/stderr only after successful stop and both joins;
before that, or after any capture failure, it returns Err.

Keep fixtures/test-only markers inside tests. Helper regression tests may live
in a terminal cfg(test) module in this shared support file; they compile in
both test binaries. If cross-binary unused convenience methods trigger
Clippy, allow dead_code only on those specific public helper methods with a
reuse comment, never on the entire module/crate or production code.
