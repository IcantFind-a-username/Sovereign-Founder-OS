# S0-05 — 升级、恢复与真实交接试演

**Revision 2 · Spec Frozen · 执行角色：worker。**运行状态唯一见 [backlog](../../../backlog.md)。分派前必须由 controller 填入当前 base_commit、卡 blob 与唯一报告路径；未填不得施工。

## 目标与前置

用隔离的可运行 fixture 验证调度链，并完成至少一次真实 Luna worker→强模型 reviewer 回报。

S0-01、S0-02、S0-03、S0-04、S0-05A 全部验收。试演必须经已实现的 CLI 入口调用，验证 controller 实际可用路径，不只直接调用库函数。

## 精确写入集合

- scripts/codex-control/rehearsal.test.mjs

另允许 controller 指定的本卡单一 worker report 文件。队列、卡、protocol/contracts、角色规范、全局 gate 与其他卡文件禁止 worker 改动。实现校验工具的卡只获准修改上列对应工具与测试，不因此取得改变自己验收标准的权限。

## 接口与做法

调用前置工具的已冻结公共接口；不修改前置工具来迁就试演。当前 native Agent 工具负责显式派发，模型取自 [角色规范](../models-and-goals.md)。

1. 固定三条 fixture：直接成功；一次失败后成功；跨 revision 保留第一次失败、第二次失败进入 fallback 并独立复核。
2. 加入中断恢复和错误 head，确认不重复消费已终结 attempt。临时仓库实际构造 [protocol §9.6.1](../protocol.md) 的 B/C/W/R/M，证明 claim 不污染源码写集、报告不冒充候选 HEAD、集成仅有获准记录差异。
3. Controller 建立合成临时 Git fixture，给真实 Luna worker 一张仅改 fixture 文件的小卡；用强模型独立审阅其 diff。生产仓库的实现写集仍只限本卡测试文件。
4. 对显式标明为模拟的两失败 fixture，实际分派强模型 fallback，并将结果交另一独立 reviewer。记录调用参数、任务 ID、作者/审阅者及 CLI 结果；不能仅在 JSON 中换模型名称。
5. 真实模型回报与注入的模拟失败清楚分开；不为试演制造真实产品失败。试验结束核实 writer 已停止、锁正常释放，再由 S0-06 审核 controller 交接。

按 [protocol](../protocol.md) 报告 candidate、diff --stat、新文件、真实检查、复用/新增工具和剩余问题；worker 交付即停，controller 分派独立 reviewer。两次失败与环境阻塞按该协议处理，不能在本卡另定一套。
