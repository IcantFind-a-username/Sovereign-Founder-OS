## Actual browser matrix

Execute all cases with the real server; record exact browser/version, viewport,
locale, steps and observed result. Minimum viewport set is **375×812** and
**1280×900**, both English and Simplified Chinese. Capture initial and completed
states for each pair; include failure/focus evidence separately.

1. `browser_initial_and_bilingual_layout`: one initial GET; boundary notice,
   all four semantic cards and all discovery fields, $2,500/Lead fixture,
   guidance and exactly four action controls. Change language in both
   directions; current catalog text, `document.lang`/aria-pressed and money
   rendering update without requests. No clipped/overlapping text or horizontal
   page scroll at either viewport; narrow actions are full width.
2. `browser_four_actions_search_guidance_reset`: price → $3,500, promotion →
   Customer, search → fixed query/two hits, Reset → complete original fixture.
   Observe correct ordered guidance, suggested-button emphasis only, final
   scoping-call/completion text with no claim of contacting anyone. Search is
   initially hidden, expands on search, survives the two changes, hides on
   Reset; Reset preserves current locale. Also execute promotion before price
   and repeat idempotent actions. Network bodies contain only the fixed action.
3. `browser_busy_concurrent_clicks_and_current_locale`: browser interception
   delays one genuine POST response. Four actions disabled, aria-busy true,
   old state displayed unchanged, no optimistic success. Rapid/repeated click
   attempts emit no second action. Switch language while waiting; release the
   real response and verify current locale survives, whole state updates,
   busy clears, original action receives focus. Interception creates no route.
4. `browser_failure_hides_old_state_and_reload_reconciles`: after a rendered
   snapshot exercise browser-injected network abort, non-200 typed error, bad
   JSON, and invalid metadata/required field. In each case old business/search
   content is hidden, actions disabled, busy cleared, generic static bilingual
   failure focused/announced, no error payload echoed and no retry/second POST.
   Include a forwarded POST whose server response is discarded; compare a
   subsequent real GET to confirm the UI does not guess application/rollback.
   Remove injection and reload: one GET, no repeated POST, actual server state
   shown; fresh browser locale/view defaults. No persistent storage is used.
5. `browser_keyboard_targets_contrast_motion`: use real Tab/Shift-Tab and
   Enter/Space across language/actions; visible focus, logical order, no trap,
   search aria-controls/expanded and live guidance region. Record computed
   hit-box sizes ≥44×44 CSS pixels and actual foreground/background contrast
   ≥4.5:1 for normal text in relevant default/selected/suggested/error states;
   explain the calculation/tool used. Inspect reduced-motion emulation and
   confirm no necessary animation. Do not claim a screen-reader/user study
   was performed from DOM or keyboard inspection alone.
6. `browser_network_and_capability_closure`: capture browser requests through
   every case, including startup/favicon/reload; application-origin traffic
   must use only the eight method/path pairs in standalone-v2. No remote
   resources, unexpected calls, credentials/cookies, polling, browser storage,
   workers, redirects, or automatic POST. Cross-check response headers with
   accepted server evidence and review source for capabilities network logs
   alone cannot disprove. Browser-internal traffic is separately identified,
   never silently dropped to manufacture a passing eight-route count.
