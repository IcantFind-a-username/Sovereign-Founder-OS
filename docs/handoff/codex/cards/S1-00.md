# S1-00 — Playground 接口与边界迁移设计

**Revision 1 · Spec Frozen（架构任务）· 角色：architect。**本卡可以交强模型；它的输出通过独立审查后，后续功能卡才可交 Luna。实际认领/完成见 [backlog](../../../backlog.md)。

## 目标

把既有 standalone-v2 计划转成小模型可施工的确切接口和逐阶段门迁移。维持原产品兼容性与 synthetic leaf 永久不变量，解决 Task 1 精确快照阻止正常扩展的问题。

## 事实与规范

- 规范：[standalone-v2](../../../superpowers/plans/2026-08-14-consultant-playground-standalone-v2-implementation.md)。
- 源码：crates/consultant-playground/src/lib.rs、domain.rs。
- 当前 source_boundary 在 tests/support/boundary.rs 比较完整 token 形状，physical_boundary_source.rs 固定两个源文件。
- manifest_boundary 在 tests/support/manifest.rs 拒绝全部依赖/features。
- 这意味着动作、模块、DTO、serde 和 tiny_http 都不能在现有检查不变的情况下直接加入。不要把这个预期 RED 当 Luna 第一次代码失败。

## 精确写入集合

不得编辑产品源码、已有安全 gate、既有 v2 计划或 RFC 来获得宽松方案。若确实必须更改规范，提交具名设计阻塞或独立治理卡，不在本卡自行放行。

## 必须一次确定的接口

1. 沿用当前 graph，不引入 superseded v1 的另一套实体/ID 模型。
2. 四个 unit action 的可达状态、重复语义、Reset 与只读结果；不能接收自由参数。
3. session、graph、动作、DTO 之间的 Rust 可见性和准确函数签名。共享模块所需接线包含在写集。
4. one-way read model 字段、catalog key、双语占位符和 guidance 状态表；批准版本中不留“实现者自行决定”。
5. POST 原始 body 边界、请求字段、错误码/status/headers、Host 验证与完整八 route 清单。
6. server 生命周期/测试启动方式，让 server 先于浏览器交互验收、CLI 再增量接线。
7. serde/serde_json/tiny_http 的精确批准来源、kind、features/default-features；不能泛开整组依赖。
8. 每张卡的精确文件和命名测试，包括原 source/manifest 检查演进的单独卡。

## 门迁移的交付格式

对每个旧断言，写清“永久不变量”还是“Task 1 阶段快照”，列替代检查、合法 fixture、至少一个恶意变异，以及哪张迁移卡负责。

S1-G01 先为下一张动作卡迁移现有 source checker；S1-G02 在 DTO 前迁移精确 dependency 检查。后续新增模块/依赖按需要生成 G03 等独立窄卡，不能一次开放所有未来能力。迁移卡在旧源码上保持绿色，又能证明被冻结的下一阶段合法形状与恶意形状的区别。

继续复用 RustLexer、source_boundary、production_sources、source_root_boundary、manifest_boundary、ManifestFixture、JSON/符号链接 fixture。禁止复制第二套扫描器、从候选代码自动刷新 expected shape、移除全部源码检查或退化为关键词黑名单。

## 验收

- 独立 reviewer 确认接口/状态/字段/依赖可机械实现，没有绕过 v2 的入口。
- S1-G01/G02 与紧随功能卡配对，不形成“先删除 gate 后补回来”的窗口。
- 后续卡仍有未冻结部分就保持 Blocked design，不能将目录级范围假装精确白名单。
- 只有任务索引与新契约改变；源码、旧计划和 RFC 保持原样。
- git diff --check、./scripts/test_changed.sh 通过。

验收后把 S1-after-design.md 中对应卡升级为单独 Frozen 卡，并将旧节替换为链接；不保留两份规范正文。每张未来新增卡先注册 backlog，再由 controller claim。
