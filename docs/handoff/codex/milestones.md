# 开发里程碑索引

本文件只维护阶段、任务依赖方向与远期设计意图。**详细接口、文件与验收以 cards/ 中的单张卡为准；任务认领/完成以 [backlog](../../backlog.md) 为准。**这里的“待前置”等是规划说明，不是另一个运行状态库。见 [总入口](README.md)。

## 12. 细分任务目录

**这是依赖图，不是一口气派出的待办清单。**只把当前阶段已冻结、可验收的小卡晋级 Ready；远期任务描述足够定位，但不预先编造尚未确定的 Rust API。

状态约定：

- **架构卡：**强模型处理，完成后冻结接口/边界并更新子卡。
- **待前置：**范围已能切分，但依赖尚未验收，Luna 不可领取。
- **研究卡：**输出可运行试验和选型结论，不自动晋级产品。
- 所有表中的新增测试都是 **planned**；不代表仓库已有或运行通过。
- 每张代码卡包含新增测试及最小实现，不能先提交一个使 workspace 长期变红的“纯失败测试阶段”。
- allowed_write_paths 必须在分派时扩成精确文件，尤其补齐模块声明与新增测试入口。表中的目录仅用于规划，不能当无限写入授权。

### 12.5 S4–S6：真实产品之前的设计与复用队列

这些不是可直接交给 Luna 的“大包任务”。强模型应选用既有 backlog，或先把缺口拆成单卡后再执行。

| ID | 工作方向 | 当前依赖与裁决 |
| --- | --- | --- |
| **S4-00 架构整合** | 盘点 owner session、Vault 1A/1B/1C/1D、capability 接线、freshness 和恢复实际落地情况 | 复用现有 backlog/RFC；不能把 docs 打勾当代码完成。 |
| **S4-01 存储清单** | 真实业务图、文档、缓存、索引、队列和日志的闭包 | 依实际 ActiveV2 与 key domains；明确单一写入者和迁移。 |
| **S4-02 产品入口** | owner-authenticated 的真实公司/客户录入与查询 | 构造必须依赖真实 OwnerSession 和 ActiveV2 类型，不能用 bool/fixture。 |
| **S4-03 真实本地模型** | 将合成验证的 worker 接到允许的 protected input | RFC 0004 的完整执行路径和恢复门槛；零出网等测试必须在真实执行面运行。 |
| **S4-04 使用与恢复验收** | 真实草稿、版本、关闭重开、干净环境恢复与恢复后核验 | 无恢复就不扩大自治；真实用户测试单独取得实际观察。 |
| **S4-L00 真实法务放行** | 具体试点市场、业务和地区规则包的专业复核与产品宣称审核 | S3-L04、适用 S4 数据/owner 门；真实法务业务或法律强制规则启用之前完成。外部法律审核不是强模型代码验收；不得以合成结果代替。 |
| **S5-00 凭据与效果设计** | 首个 email/provider broker 与 exact effect contract | 复用 owner/exact-effect 规范；真实 recipient、bytes、scope、expiry 绑定。 |
| **S5-01 单一连接器** | 一个服务、一个动作、明确错误分类 | 先本地/模拟服务契约，再经批准的真实动作；不把研究授权当发送授权。 |
| **S5-02 故障与不确定状态** | 超时、重复、撤销、过期、发送后 crash 的核对路径 | Indeterminate 不自动重发；不能单靠框架 retry。 |
| **S6-00 经营迭代** | 今日优先级、任务复盘、成本/应收解释与更丰富技能 | 真实使用反馈决定下一卡；专业/地域规则另行审核。 |
| **S6-01 扩展能力评估** | MCP、外部 ERP、桌面容器、向量搜索和专业包 | 按具体需求一次引入一项；Mesh/多租户/市场继续 Research。 |
