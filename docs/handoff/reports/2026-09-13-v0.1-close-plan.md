## 0. Coordinator decision (blocks product 1C0 work)

ROADMAP v0.1 **exit criterion 2** (`ROADMAP.md:201-205`) requires a product
outbox effect to carry independently authenticated 1C0 approval, and forbids
the application / Vault / effect layer from minting a parallel owner signer.

That wording **conflicts** with accepted-as-Draft fixture governance:

- RFC 0006 G2 (`rfcs/0006-synthetic-owner-session-exact-effect-fixture.md:46-54`)
  blocks **product** use until 1B1 + 1C1 + 1D `ActiveV2` + protected-payload
  review (those are **v0.2** Vault gates).
- The **current** fixture plan is
  `docs/superpowers/plans/2026-08-14-synthetic-owner-exact-local-outbox-v2-implementation.md`
  (v1 plan in the sibling file is **Superseded — do not execute**).
- v2 Task 0 (RFC 0002 closed profile `low-risk-effectful` / `write_rfc5322`)
  has **not** landed (`rg` finds neither string in `rfcs/0002-*.md`).
- Substantial **v1-shaped** code already exists (`crates/owner/`,
  `crates/authority/src/broker/`, `fixtures/owner-webauthn/`, TSV runners).
  v2 **rejects** HMAC IPC, hidden broker child, and a second listener.
- Product still mints `owner_approval_key` in
  `apps/cli/src/workspace/kernel_exec.rs:154-177` and documents
  “no authentication” in `apps/cli/src/ui.rs:4-6`. Pin test:
  `an_unauthenticated_local_post_can_approve_today_1c0_pin`.

**Recommended close interpretation (honesty-close):** treat v0.1 1C0 as
**fixture mechanism proof + product honesty**, not product admission. Amend
ROADMAP exit 2 (owner-approval diff) so it matches RFC 0006 G2. Keep the
literal product-signer ban as a **v0.2** gate.

**Forbidden without that amendment:** any ticket that wires WebAuthn/session
onto `/api/workspace/decide`, removes `kernel_exec` owner-key minting, or
continues the superseded v1 broker (`BrokerReady` / HMAC / hidden mode).

Until Wave G0 lands, Composer 2.5 must only take honesty, integrity, 1A
engine, and fault-test tickets below.
