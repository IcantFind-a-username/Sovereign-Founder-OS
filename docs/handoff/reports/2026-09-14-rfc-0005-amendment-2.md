## Closed in this amendment (body + Amendments §)

1. **Recovery session → new-device registration.** A read-only recovery
   session zeroizes password / PWK / RecoveryKEK / DBK before return.
   Authorization cannot restore those keys. New-device registration is now
   a distinct ceremony after that session ends: re-enter the recovery
   password; consume a one-use authorization; unwrap, wrap for the new
   device, verify, and zeroize in one brief flow. Device registration MUST
   NOT rely on secrets retained from the prior read-only session.
2. **Reversibility is stage-bounded.** `PendingV2` abort/crash/revoke
   remains reversible. After `ActiveV2` accepts new business writes,
   software rollback MUST continue to support the v2 data format; otherwise
   a separate data-migration RFC is required. Direct “go back to legacy
   writers” is forbidden without that protocol.
3. **Backup stays attended.** RecoveryKEK remains offline. Unattended /
   scheduled backup is not implied. First ship MUST define founder-visible
   RPO/RTO and surface last-successful-backup plus last-restore-drill
   timestamps (Target UX; MAY be a later product milestone). Honesty is
   normative now.
4. **Dual-root ≠ independent failure domains.** Device wrap binds the
   recovery slot; recovery-slot corruption can fail normal device unlock
   even if DeviceKEK is intact. Current profile default is **A**: restore
   from backup only. Profile **B** (authorized salvage) is out of scope
   until a later amendment names it. Disaster drills MUST include
   “recovery slot corrupted, DeviceKEK still present.”

Header honesty: `Implementation:` is now `Program 1A engine Experimental
(non-product); Programs 1B+ not started`. Status stays Draft.

## Open follow-ups (do not solve on this branch)

5. **SQLCipher pin applicability.** Amendment 1 froze `4.17.0`. Upstream
   released `4.19.0` (2026-09-08) with low-risk `sqlcipher_export` / hexkey
   URI fixes. Those entry points are banned here, so the new release is not
   automatically exploitable. An applicability + dependency-diff review is
   required before freezing the shipping binding combo. Merge with the
   future binding-admission amendment. No silent bump.
6. **Loosen RFC binding to exact test filenames / “exactly N tests” /
   download-failure-must-revise-RFC rules.** Move those to versioned
   implementation plans and verify configs. Exact on-disk format, key
   purposes, and fail-closed semantics stay in the RFC.
